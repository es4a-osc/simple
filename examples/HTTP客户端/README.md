# HTTP客户端示例

演示异步请求、JSON、流式文件表单、文件选择器 URI、进度、取消及销毁。使用默认应用图标。

需要包含 `HTTP客户端` 的运行库 JAR；仅更新清单不能编译该示例。组件用法见 [HTTP客户端](../../../sdk/docs/HTTP客户端.md)。

## 准备可控测试服务

本例的自检依赖以下 HTTP 接口。请先在独立测试环境准备服务，并在“服务地址”填写设备可访问的根地址；默认值为 `http://127.0.0.1:18766`。示例 APK 本身不提供服务端。

| 接口 | 返回约定 |
| --- | --- |
| `GET /get` | 200，返回简短的 UTF-8 正文 |
| `POST /echo` | 200，返回收到的正文及 Content-Type，便于核对中文 JSON |
| `GET /created` | 201，正文非空 |
| `GET /empty` | 204，正文为空 |
| `GET /missing` | 404，返回错误正文 |
| `GET /redirect` | 302，Location 指向 `/get` |
| `GET /large` | 200，正文大于 100 字节 |
| `GET /slow` | 等待 5 秒后返回 200 |
| `POST /upload` | 接收 multipart 的 `attachment` 文件及可选 `memo` 字段，返回文件名、实际字节数、SHA-256 和附加字段 |

如果服务运行在开发机回环地址，先选择已连接且启用 USB 调试的设备，再映射端口。`设备序列号` 应替换为实际值，`adb` 需可从当前终端调用：

```powershell
adb devices
adb -s 设备序列号 reverse tcp:18766 tcp:18766
```

## 设备端验证

编译、安装并运行本项目，通过 Escrcpy MCP 或手动执行以下操作，检查页面结果与服务端记录：

1. 点击“GET / JSON 自检”，预期检查 GET、JSON、201、204、404、302、响应上限和读取超时，最后显示“基础自检通过”。请求链直接从终止事件中发起，同时检查忙碌拒绝和事件重入。
2. 点击“上传本地文件”，服务端应收到 `httpclient.txt`、附加中文字段及正确文件内容。初始化会在应用内部准备这个小文件，服务端摘要应与原内容一致。
3. 点击“选择文件并上传”，用系统选择器选择一个文本文件，预期显示其 `content://` URI。核对服务端收到的文件名、字节数及摘要；取消选择后应能重新选择。
4. 点击“启动慢请求”，在 5 秒内点击“取消请求”，预期只出现一次取消事件，并由取消事件启动一个新 GET。等待旧慢请求结束后，新的结果应保持有效。
5. 点击“销毁检查”，第二个组件发起请求后立即销毁。等待超过 5 秒，不应出现它的终止事件，第一个组件仍可完成自检。

结束后关闭测试服务，并移除本轮创建的端口映射：

```powershell
adb -s 设备序列号 reverse --remove tcp:18766
```

## 主机测试

纯 Java 传输测试位于 `tests/simple/runtime/components/impl/android/util/HttpTransportTest.java`，已接入现有 JUnit 和 `simple.AllTests`。在 Simple 源码目录按原有流程运行 `build.bat --no-pause`，包含构建及测试。

这些单元测试自行启动随机回环端口的 HTTP 服务，结束后自动关闭，不依赖上表中的设备测试服务。Android 主线程、组件事件绑定、内容 URI 和生命周期通过真实示例 APK 验证，不使用手写 Android 或运行库替身。
