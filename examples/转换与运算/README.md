# 转换与运算

文档类型：运行库使用示例。核对日期：2026-10-19；依据：当前运行库源码、清单及本项目。

演示普通类型与进制转换、数值和字节集互转、十六进制字节编码、数值格式化及金额格式化，并演示反正弦、反余弦、立方根、斜边计算、范围随机整数和指定小数位舍入，保留角度弧度、随机数、UCS2 和 MD5 演示。

在 ES4A 添加本目录的 [project.properties](project.properties)，使用包含独立“进制转换”方法集、格式化数值、金额格式化、新增转换接口及六个数学接口的运行库编译运行。源码：[主窗口](src/simple/examples/conversions/主窗口.simple)。

1. 点击“运行演示与自检”，核对固定结果，检查转换与数学接口，并展示数值格式化；金额 `12.3` 得到 `12.30`，`1.005` 得到 `1.01`；反正弦、反余弦换算为角度后分别约为 30°、60°，-8 的立方根为 -2，直角边 3、4 的斜边为 5。
2. 在第一个输入框填写十进制数值，点击“数值转字节集与还原”，观察字节排列及还原结果。
3. 在第二个输入框填写十六进制文本，点击“十六进制数值与字节解码”，对照数值解析与字节解码；可试 `78563412`、`12ABC`、`GG` 和空文本。

数学常量与普通数学函数统一归入“数值运算”方法集；全局短名仍可使用，完整限定名例如 `simple.runtime.数值运算.求斜边(3, 4)`。本示例同时演示全局短名和完整限定名调用。

反正弦和反余弦的输入有效范围为 `[-1, 1]`，返回值单位是弧度，越界返回 `NaN`。立方根支持负数。斜边计算使用两条直角边的绝对值，并避免中间平方运算造成不必要的溢出或下溢。

`取随机数()` 仍返回 `[0, 1)` 的双精度小数；`取随机数(最小值, 最大值)` 返回包含两端的随机整数，允许负数及完整整数范围，上下限相同时直接返回该值，反向范围报非法参数错误。例如 `取随机数(1, 6)` 可模拟骰子，每次点击自检重新取值。

`四舍五入(数值, 小数位数)` 按 `HALF_UP` 舍入并返回双精度数值；例如 `四舍五入(1.005, 2)` 得到 `1.01`，`四舍五入(-145, -1)` 得到 `-150`。位数为 0 时舍入到整数，-1 为十位，-2 为百位。输入应为有限数值，输出仍可能有浮点表示误差；需要固定两位的金额文本时使用“格式化金额”。

“格式化文本”“格式化数值”“格式化金额”统一归入“文本操作”方法集，分别处理通用文本、数值显示和金额文本的格式化。

`文本操作.格式化数值(格式, 数值)` 使用 `DecimalFormat` 格式：`0` 为必填数字、`#` 为可选数字，支持分组、百分比、科学计数及以 `;` 分隔的正负数子格式。例如 `格式化数值("0000", 42)` 得到 `0042`；在中文或美国区域下，`格式化数值("#,##0.00", 1234.5)` 得到 `1,234.50`，`格式化数值("0%", 0.1251)` 得到 `13%`，`格式化数值("0.00E0", 12300)` 得到 `1.23E4`。格式语法固定，显示数字和分隔符等符号随系统默认格式区域变化，例如德国区域的分组结果为 `1.234,50`；示例直接展示系统结果，不修改区域设置。

数值格式化沿用 `HALF_EVEN`：恰好位于中点时向偶数舍入，格式 `0` 下 `2.5` 得到 `2`、`3.5` 得到 `4`。输入是双精度数值，格式化不能恢复浮点运算或大整数转换时已经丢失的精度。负零、`NaN` 和无穷大按格式化器规则显示；非法格式报非法参数错误。此接口生成显示文本，精确的十进制金额文本仍使用下方“格式化金额”。

`文本操作.格式化金额(金额)` 直接解析十进制文本，固定保留两位小数，采用 `HALF_UP` 舍入；中点向远离零的方向取舍，例如 `-1.005` 得到 `-1.01`。输出固定使用 `.`，不加货币符号或千分位，零不保留负号。允许正负号和科学计数；不接受首尾空白、分组分隔符、货币符号、`NaN` 或无穷大。非法文本会转换为 Simple 的非法参数错误，不按零处理。数值规模受十进制运算及可用内存限制。

“进制转换”方法集提供 `十六进制(值)`、`十六进制到长整数(文本)`、`整数到二进制(数值)`、`二进制到长整数(文本)`，可使用全局短名，也可写完整限定名，例如 `simple.runtime.进制转换.十六进制到长整数("FF")` 得到 `255`。原先带 `数据转换.` 的这四个调用需改为 `进制转换.`。

`十六进制` 先将变体转为长整数，小数按变体规则截断，负数输出 64 位补码；`整数到二进制` 对负数输出 32 位补码。两个文本解析方法按有符号长整数解析，不将最高位为 1 的文本自动解释为负数。因此 `十六进制(-1)` 的结果不能由 `十六进制到长整数` 还原，而 `二进制到长整数(整数到二进制(-1))` 得到 `4294967295`。字节集的十六进制编码仍属于“编码转换”，数值与字节集互转仍属于“数据转换”。

`数据转换.取字节无符号值(字节)` 返回普通整数型，范围为 `0～255`；例如字节 `-1` 得到 `255`，字节 `-128` 得到 `128`。这是按无符号方式解释字节，不是引入新的整数类型；普通“到整数”转换仍保留字节的符号。

整数转换为四字节小端，长整数和双精度小数转换为八字节大端。小数转换处理 IEEE 754 位模式，不是把小数文本编码为字节；还原时只取前四或八字节，不足长度返回 0。

十六进制字节解码沿用宽松规则：不跳过空白或分隔符，奇数长度忽略末尾字符，非法字符仍按低四位映射。例如 `12ABC` 得到 `12AB`，`GG` 得到 `00`。不要把此接口当作格式校验器。进制数值解析则不接受前缀或首尾空白，失败及溢出返回 0。

普通类型转换保持现有行为，例如“到整数”会将 `1.5` 截断为 1，不能作为严格输入校验。MD5 用于演示摘要，不用于密码存储；UCS2 文本转义与 UTF-8 字节编码是不同操作。
