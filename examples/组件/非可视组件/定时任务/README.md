# 定时任务示例

演示系统非精确定时：启动本应用服务、启动主界面、覆盖和取消任务。无需额外权限或第三方依赖。

1. 保持默认延迟 5 秒，点击“设置单次服务任务”。到期后显示服务收到的任务编号 101、文本参数及执行次数；系统可能延迟派发。
2. 点击“设置循环服务任务”，覆盖编号 101 的服务任务。重复间隔默认 60 秒，实际间隔可能被系统延长；观察两次执行后点击“取消服务任务”。
3. 点击“设置启动应用任务”。系统派发后，在窗口的“程序被启动”事件中读取编号 102 和文本参数。后台弹出界面受 Android 限制，提交成功不代表界面一定出现。
4. 可分别取消服务任务和启动任务，重复取消不会报错。“清空服务记录”只清空演示结果，不取消任务。

[主窗口](src/simple/examples/tasks/主窗口.simple) 负责设置及取消任务；[任务服务](src/simple/examples/tasks/任务服务.simple) 在工作线程接收意图并写入私有 task-result.json，使用消息向仍存在的窗口反馈。窗口重新打开后可刷新累计记录。服务使用自身 Context 的文件目录，不依赖窗口存活。

单次任务可省略重复间隔；再省略文本参数时传递空文本。示例输入有文本时使用带参数重载，清空文本后使用无参数重载。例如：

~~~simple
定时任务1.设置服务任务(101, 取包名() & ".任务服务", 5000)
定时任务1.设置启动任务(102, 5000, "打开应用")
~~~

时间参数单位为毫秒，示例输入使用秒并转换；完整接口的重复间隔为 0 表示单次。服务任务由服务限定名及编号共同标识，启动任务按编号标识。相同身份重新设置会覆盖原任务，不同身份可以并存。意图通过“任务编号”和“参数”两个附加值传递数据。

任务在窗口销毁后继续由系统管理；取消不打断已经开始处理的服务。后台服务、后台界面启动及省电策略可能限制执行，本示例不提供保活、强制停止后唤醒、重启恢复、亮屏或解锁功能。应用进程结束后，系统可能拒绝后台服务启动，此时不会收到服务回调；重新打开窗口也不会补执行。离开示例前请显式取消循环任务。
